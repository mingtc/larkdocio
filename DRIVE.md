# DRIVE.md — larkdocio Drive (folder / file) capability matrix

**The single source of truth for what larkdocio's Drive surface supports** — the **fifth**
living matrix, alongside [`/BLOCKS.md`](BLOCKS.md) (docx blocks), [`/SHEETS.md`](SHEETS.md) (the
Sheets surface), [`/BASE.md`](BASE.md) (the Base surface) and [`/PERMISSIONS.md`](PERMISSIONS.md)
(which Lark scopes each operation needs).

> **Citations into `dev/`, `progress/` and `requirements/`** in this file are provenance
> notes **in the dev repo**, pointing into the maintainers' private records, which the public
> repository does not carry. Read each as provenance for the fact stated beside it.
> A recorded API response is cited at its `tests/captures/…` copy where the repository carries
> one; a recording cited under `dev/` is a maintainers' record the repository does not carry.

**This file is BORN BEFORE THE CODE IT DESCRIBES, on purpose.** The Base read spec wrote the lesson down
after the Sheets arc paid for learning it late — *"the matrix is born in this tranche, not after
it"* — and the Drive spec § D1 ruled it in for Drive with a second argument that is specific to this
surface: **Drive has the largest OUT list in the project.** `capabilities()` reports what
*ships*; it has no row shape for *can-but-won't* (the sharing family), for *structurally
unreachable* (`USER`-token-only search and subscriptions), or for *the API has no such verb*
(purge / restore). Without this file a future contributor re-discovers each of those by probing —
and for the sharing family that means probing a call that **mints a public capability URL**. A
written row is cheaper and safer than a re-probe.

**A `not-yet-R<n>` row here is a decided boundary, not a to-do — and that is the point.** The
Drive ladder is **R1 folder read → R2 upload → R3 organize → R4 extras**, and **R1 was approved
first; every rung above it opens VERB BY VERB, each by its own ruling** — never a whole rung at
once. A maintainer ruling opened the **`file_version` half** of R4; LD-434/LD-449 opened single-shot and
chunked **upload** (R2); the 2026-08-14 product ruling (LD-467) opened **create a folder**, and
the delete of a file this library uploaded, out of R3. Statistics, view records, likes, the
wider export and raw-file bytes stay staged and unapproved (the Drive spec § The ladder, annotated
`superseded_in_part`), as does the rest of R3.

**Do not read a count out of this paragraph.** The Operations table below is the census, and it
is the one to count — the status column is the answer, and today the shipped rows outnumber the
staged ones several times over. (This paragraph used to open *"So most rows here say 'not yet'"*
and *"R1 plus exactly one rung of R4 and nothing else"*; both were true when the ladder opened
and neither has been since the upload and folder-create rulings. **LD-586** replaced them with
the derivation rather than a re-typed number — the same treatment LD-585 gave `:92`, `:130` and
`:133`, whose fourth instance this was.)

**Scopes are not authored here.** Where a row names a Lark scope it is quoting the single source,
`larkdocio.permissions`, whose maintainer-side projection is
[`/PERMISSIONS.md`](PERMISSIONS.md). Add an operation and its scope row belongs there — adding
one here would be a second, unguarded assertion of the same fact.

Two disciplines keep this file honest — the `SHEETS.md` / `BASE.md` standard, unchanged:

1. **Verified evidence only.** Every row is sourced from **shipped code/tests**, from the
   **Drive spike** (`dev/drive-spike/2026-08-07-drive-surface-map.md`
   and its [`captures/`](tests/captures/drive-spike/captures/) — two probe rounds, 12 captures (10 of them carried
   there), 17 live calls, zero writes), or from the pinned SDK's own models. Nothing is speculated: anything not
   observed is an honest **`uncaptured`**, never a guessed status.
2. **Drift-guarded.** [`tests/test_drive_md_matrix.py`](tests/test_drive_md_matrix.py)
   cross-checks this file against the code that exists **today**: every status is a recognised
   slug that the vocabulary table defines, every row naming code names **real importable** code,
   every cited repository path exists (checked in the maintainers' working repository, which
   also keeps the evidence under `dev/` and `requirements/` that the public one does not carry),
   every operations row carries an evidence pointer, and the
   **dispatch region is bidirectional the moment a dispatcher exists** — a branch added without a
   row, or a row naming a branch nobody wrote, reddens. A deliberate-defect test proves the guard
   bites rather than merely running.

> **Where the surface stands (LD-324).** The vocabulary landed first (LD-323): the URL validator
> recognises `https://<host>/drive/folder/<token>`, reports the type **`drive`** and hands back
> the **folder token** (`src/larkdocio/common/url.py`, `URL_PATH_SHAPES`). **The enumeration now
> exists too.** `src/larkdocio/drive/` ships a throttled, READ-only client for the listing
> endpoint (paged to exhaustion on Lark's opaque cursor, `option` never sent), a depth-first
> walker with a visited-set and disclosed caps, and the two non-SDK legs — the caller's own root
> folder and a folder's own title — on the existing raw-HTTP core. The two new endpoint families
> carry their permission rows, **empty and deliberately not guessed** (register row 6).
> **The `type`→reader dispatcher exists** (`LD-325`, `larkdocio.drive.dispatch`): a pure,
> offline selector that closes the `sheet`/`bitable` seam, resolves shortcuts behind the
> visited-set, and discloses `file` and unknown types rather than reading or dropping them — so
> the dispatch table below is a **bidirectionally-guarded** region, not a placeholder. The
> dispatcher **selects a reader; it invokes none** — `read_folder` is what invokes them.
> **The read surface is complete.** `larkdocio.drive.read_folder()` runs the readers over
> the walk and returns a structured `FolderRead` plus a one-document rendering, a child that
> fails never fails the walk, and `FolderRead.accounted()` proves `children == read + disclosed`.
> The front door tells the truth in the same breath: a `folder` CLI verb reads a folder tree,
> `download` refuses a folder URL by naming that verb, `capabilities()` reports the `drive-read`
> surface (its scopes empty and recorded-unknown), and the shipped guide carries a runnable
> recipe. The measured reason this rung
> was worth its stories: on the maintainer's real tree the spike found **27 of 29 documents (93%) already
> readable by shipped larkdocio code, and zero of them reachable** (§ VII.2).
>
> **The surface also writes — four direct-call legs, each its own `capabilities()` surface:**
> named versions (`drive-versions-write`), who has access (`drive-access-write`), one file into
> a folder (`drive-files-write`) and one folder under a parent (`drive-folders-write`); the
> Operations table below is the census. **The versions leg came first (LD-409).** A maintainer ruling
> opened R4's `file_version` half:
> `list_versions` reads a file's named versions and `create_version` adds one, returning the new
> token **paired with the head revision read immediately before it** — the pairing is the whole
> point, because a version token resolves to nothing on its own (register row 11).
> `larkdocio.drive.ops.read_only()` therefore answers `False` for the registry as a whole now;
> the claim it used to make was **re-scoped, not deleted** —
> `read_only(larkdocio.drive.ops.ENUMERATION_OPS)` is still `True`, and the folder-read surface
> is still read-only end to end. `delete_version` is measured working and deliberately does
> **not** ship (register row 7).

## Status vocabulary

One small, explicit slug set — the `BLOCKS.md` / `SHEETS.md` / `BASE.md` precedent, with the two
slugs this surface needs that the others did not. `uncaptured` is the honest-unknown slug.

| Status | Meaning |
|--------|---------|
| **shipped** | Built and tested in shipped larkdocio code. Its code anchor resolves to real code — the drift guard enforces this. |
| **not-yet-R1** | Inside the **approved** R1 rung, not landed yet. The row names the story that lands it, so "not yet" carries an address instead of a shrug. |
| **not-yet-R2** | Deferred to the **upload** rung. Staged and **unapproved** — reopening is a maintainer ruling, not a build decision. |
| **not-yet-R3** | Deferred to the **organize** rung — its remaining verbs, enumerated with a reason each in `larkdocio.drive.folders_write.R3_NOT_SHIPPED` rather than retyped here: move, rename, copy, organise-a-folder's-children-by-a-rule, folder delete, shortcut. Staged and **unapproved**. **Two verbs have left this set, each by a ruling, and each transform kept its reason.** **`delete`** ships for a **file this library uploaded** (the *Delete a file this library uploaded* row below, opened by the same ruling that opened the single-shot upload) — the fence's reason is unchanged, because a destructive verb pointed at an object the caller already had is a different act from undoing this library's own upload. **`create_folder`** ships since the product ruling of **2026-08-14** (the *Create a folder* row below) — the fence's reason is unchanged there too, because the rung is shut against verbs that relocate or destroy objects a caller already had, and an additive create under a parent the caller names is neither. In both cases **only the enumeration moved**. |
| **not-yet-R4** | Deferred to the **extras** rung (batch metadata, statistics / view records / likes, the wider export, raw-file bytes). Staged and **unapproved** — with one exception ruled in by the maintainer: the **`file_version`** half now ships (see the two named-version rows below), and its arrival re-scoped this slug rather than retiring it. |
| **refused-by-server** | Lark's own API refuses it, server-declared (a typed error code, an enum). Inherited from the `BASE.md` vocabulary unchanged — the register's `1061002` rows are this class. |
| **refused-by-policy** | larkdocio refuses it by its own doctrine, and the API is not the obstacle. The sharing/permission family is the whole of this class here: a tool that can flip a document public is a tool that can exfiltrate a tenant. Reopening needs a maintainer decision, **not** an API change. |
| **structurally-unreachable** | Cannot be reached by this library **at all**, for a reason no scope grant fixes — the operation is `USER`-token-only and larkdocio is tenant-token-only, or the open API has no such verb. |
| **uncaptured** | Not observed. An honest unknown — never a guessed status. |

## The manifest's `revision` field — what each child type actually exposes

A **change-detection ledger** is the folder read's first machine consumer: walk a folder, record
what is there, and on the next run fetch only what moved. `folder --dump` supplies the traverse
half, and its per-child `revision` is the anchor that half can honestly offer. The rule the whole
field is built on: **larkdocio makes no extra API call for a revision, and never fabricates one.**
Where the read this walk already performed left an anchor in hand, the row carries it; everywhere
else the row reads `availability: "unavailable"` **with the reason**. There is no third state, and
a missing anchor is never laundered into `0` — `0` is a revision a real spreadsheet and a real
Base table can both hold.

| Child type | Reader surface | Revision in the manifest | Anchor | Why |
|------------|----------------|--------------------------|--------|-----|
| `docx` | `docx` | **available** | `document.revision_id` | Returned by the block read the walk already made, so it is free. It advances one per edit operation, which is what makes it usable as a change anchor. |
| `sheet` | `sheets` | **available** | `properties.revision` | Rides the values reply the read already made, so it is free. Spreadsheet-scoped: the first tab reporting one answers for the document. A reply carrying none is marked unavailable, never reported as `0`. |
| `bitable` | `base` | **unavailable** | — | A Base's anchor is **per table**, not per document, so there is no single number for a Base child and none is offered. `larkdocio.base.read_base()` carries the per-table `revision`. |
| `folder` | `drive` | **unavailable** | — | A container, not a document; it has no revision. Its children carry their own rows. |
| `file` | — | **unavailable** | — | Disclosed, never read — so no anchor is obtained for it. |
| *any skipped child* | — | **unavailable** | — | The child was not read (Lark refused it, the reader raised, the listing carried no url), so nothing was obtained to anchor on. The row still exists, with its disclosure. |

**Every row carries `modified_time` regardless.** The folder listing exposes no revision for any
child, but it does return `modified_time` for all of them at no extra call — so a ledger always
has *an* anchor for the whole folder, and a stronger one where the read supplied it.

The table above is not prose alone: it is `larkdocio.drive.manifest.REVISION_SOURCES`, and it
ships **inside** the sidecar under `revision_sources`, so a consumer reads it where it is working
rather than in a document it may never open. **The manifest itself spends no extra call for the
`docx` row** — per the no-extra-call rule above, it reports the free walk-derived anchor
(`document.revision_id`) the read already produced, never a probed one.

A cheap docx revision probe has **shipped separately from the walk** (`LD-382`):
`Client.read_document_revision(token)` costs **one** metadata call, touches no block tree, and
answers the same number `get_docx_content` would report at that moment. It exists for a ledger
that wants the anchor **without** walking the folder — checking one document between runs, say —
not for the walk itself, which already has the free anchor from the row above and gains nothing
calling it again. See `GUIDE.md`'s "version anchor a ledger compares between runs" passage for
the full semantics (monotonic, comparable only to itself across time, `None` means unknown) and
`DECISIONS.md` D-50 for what is still true and unrefuted: **there is no bulk revision route** —
the Drive `metas/batch_query` POST answers for a list of docx tokens but carries no revision
field, and every other tried batch shape came back refused — so N documents still cost N calls,
one each.
