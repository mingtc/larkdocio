# PERMISSIONS.md — which Lark scopes each operation needs

**The living permissions matrix, in the same register as [`/BLOCKS.md`](BLOCKS.md) and
[`/SHEETS.md`](SHEETS.md): touch an API-using call site, and its row moves in the same
change.** The difference is that **no requirement in this file is hand-maintained** — the
fenced table below is **generated** from `larkdocio.permissions`, which is the single source,
and `tests/test_permissions_docs.py` holds the region byte-identical to that projection. This
preamble, down to the fence, is hand-written prose *about* the table; everything inside the
fence is the projection. Edit the registry, not the generated region.

> **Citations into `dev/`, `progress/` and `requirements/`** in this file are provenance
> notes **in the dev repo**, pointing into the maintainers' private records, which the public
> repository does not carry. Read each as provenance for the fact stated beside it.
> A recorded API response is cited at its `tests/captures/…` copy where the repository carries
> one; a recording cited under `dev/` is a maintainers' record the repository does not carry.

This is the **maintainer's** view: every call site in the library, including the ones no
consumer can reach. The **consumer's** view is a different document by design — it is the
permissions section of the shipped guide (`larkdocio.guide()`), which covers only what a
consumer can actually call and phrases it in their terms.

## How a requirement gets into this table

1. **The endpoints are derived from the call site's own code** — the request classes it builds
   and the paths it names, followed through this package. A call that starts using a different
   endpoint family moves here with nobody remembering to move it, and a call that reaches
   nothing derives an empty set, which is how *"is this API-using?"* stays a derived fact.
2. **The scopes come from one table**, joined on those endpoints and on the credential pair.
   A Lark scope string exists nowhere in our own logic, so that table is the one hand-listed
   thing in the chain — and every row of it carries an evidence pointer and a verification
   label.
3. **An unknown is recorded as an unknown.** Where no scope string has ever been observed
   demanded for an endpoint, the requirement is empty **and the reason is stated**. It is
   never a guess, and an empty requirement is never a claim that a call needs nothing.

## The rule this file does not bend

**This library never widens, requests or escalates a scope. It only describes what a call requires and reports, verbatim, what Lark said when a call was denied — including the console link Lark hands back. Granting a scope is an action a workspace administrator takes in the Lark console.**

Every scope grant is a console action taken by a workspace administrator. What the library
does instead is surface Lark's own denial body, which already names the exact scope and hands
back a console link.
